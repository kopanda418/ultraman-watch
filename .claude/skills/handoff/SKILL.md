# ハンドオフ資料の更新

次のセッションが`HANDOFF.md`を読むだけで状況を把握し、迷わず作業を再開できるように、
今回のセッションで分かったこと・変えたことを反映してコミット・プッシュするスキル。

## 手順

1. 今回のセッションの内容を把握する
   - `git log`で直近のコミットを確認し、今回のセッションで何をしたかを洗い出す
   - `BACKLOG.md`の「未対応」を確認する（次に優先すべきことの候補）
   - `DECISIONS.md`に今回追加した決定がないか確認する
   - 今回のセッションで得た、コードを読むだけでは分からない気づき・ハマりどころが
     あれば拾っておく（例: 特定サイトがJSレンダリングでスクレイピングできない、
     外部サービス側の共通設定が別プロジェクトと共有されている、など）
2. `HANDOFF.md`を更新する
   - 「現在地」の表（完了/未着手）を実態に合わせて更新する
   - 「最初にやること（優先順）」を、`BACKLOG.md`の未対応上位や今回判明した
     次の課題に置き換える。完了して不要になった旧手順は丸ごと削除してよい
   - 「触る前に知っておくべき設計上の癖」に、今回新しく分かった注意点があれば
     追記する。既に書いてあることの繰り返しや、コードを読めば分かることは書かない
3. 変更をコミットし、pushする（コミットメッセージは日本語）
4. ユーザーに、次のセッションで何から始めればよいかを一言でまとめて伝える

## 注意

- `HANDOFF.md`は「次に何をすべきか」に集中させる。すでに終わった作業の詳細な経緯は
  `git log`で追えるので、そちらに任せて書きすぎない
- `internal/`配下の内容（他プロジェクトとの申し送りなど、公開したくない情報）は
  `HANDOFF.md`に書かない。`HANDOFF.md`は公開リポジトリの一部であることを忘れない
- pushは本スキルの最後に必ず行う（ハンドオフ資料が古いままでは次のセッションが
  混乱するため）。ただし、それ以外の理由で未コミットの変更が残っている場合は、
  それらを一緒にpushしてよいか先にユーザーへ確認する
