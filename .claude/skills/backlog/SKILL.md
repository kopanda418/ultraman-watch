# バックログ対応

`BACKLOG.md`（プロジェクトルート）の「未対応」セクションを、上から順に片付けるスキル。

## 手順

1. `BACKLOG.md`を読み、「未対応」の項目を確認する。項目が無ければその旨を伝えて終了する
2. 項目を1つずつ、上から順に処理する。1項目ごとに以下を行う
   - 何を求められているか、対象のコード（`scripts/`, `docs/`）を実際に読んで理解する。
     推測で直さない
   - 既存の決定事項（`DECISIONS.md`）と矛盾する変更になる場合は、実装前に必ず
     ユーザーに確認する（例: 表示順のロジックを変える、既存の除外条件を外す、など）
   - 実装する
   - 可能な範囲で検証する
     - スクリプトの変更 → `FORCE=true node scripts/collect.mjs`をローカルで実行し、
       ログと生成物（`docs/data/items.json`など）を確認する
     - PWA（`docs/`）の見た目に関わる変更 → `npx serve docs`などでローカル配信し、
       ブラウザで実際の見た目を確認する
   - `BACKLOG.md`の該当項目を「未対応」から「対応済み」に移し、何をどう直したかを
     一行で書く（詳細はコミットログに譲るので書きすぎない）
   - コミットする（コミットメッセージは日本語。`CLAUDE.md`のルールに従う）
3. 実装・検証・コミットまでは自律的に進めてよい。ただし以下は事前にユーザーへ確認する
   - GitHubへのpush（コード変更が公開リポジトリ・GitHub Pagesに反映されるため）
   - Supabase・GitHub Secretsなど外部サービスの設定に触れる変更
4. 全項目が片付いたら（またはユーザー確認が必要な項目に当たって手が止まったら）、
   そこまでの対応内容を簡潔にまとめて報告する

## 注意

- 1項目ずつ着実に進める。複数項目をまとめて1つのコミットにしない
- 対応中に新しく気づいた別の課題（今回頼まれていないもの）は、その場で直さず
  `BACKLOG.md`に追記するだけにとどめる
- `state/seen.json`など、`CLAUDE.md`で扱い方が決まっているファイルのルールは変えない
- 対応の規模が大きく、設計から詰める必要がある項目は、無理に1回で終わらせようとせず
  方針をユーザーと確認してから着手する
